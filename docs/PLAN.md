## 2. 평가 방식 (핵심)

주최 측이 우리 API에 **GET 요청**을 보내고 응답 JSON을 채점한다.

```
GET https://{team-endpoint}/answer?question_id=Q-001&question={평가 질의}

응답:
{
  "question_id": "Q-001",
  "question": "평가 질의 원문",
  "retrieved_context": "답변 생성에 참고한 검색 문서",
  "think_trace": "사고·추론·도구 사용 과정",
  "answer": "최종 생성 답변"
}
```

- 비공개 평가문제: 난이도 상/중/하 × Closed/Open 혼합, 6개 Task 유형
- 평가지표 8개: 정확성 / 근거 완전성 / 요구사항 충족 / 근거 기반(환각) / 추론 논리성 / 안전성·신뢰성(프롬프트 공격 방어) / 정보한계 대응(모르면 "확인할 수 없음") / **모든 답변에 근거 공시 표기**
- 규칙: LLM은 **HyperCLOVA X만**. 제공 코퍼스 외 데이터·외부 API 금지. 미래 예측·투자 의견 금지.

## 3. 우리가 가진 것

- `data/corpus/` — 70개사, 2023.01~2026.03, 4,204문서(XML). manifest.jsonl(문서 메타), universe.csv(기업 마스터)
  - 정기 1,054 / 주요사항 598 / 거래소 1,469 / 지분 1,083 · 정정공시 1,004건 병행 수집
- `data/share_embeddings/` — 명섭 산출물: FAISS 인덱스(257,186청크×2048d, Nemotron-3-Embed-1B), chunk_meta.jsonl(1GB), correction_map.json
  - `search_lib.py` Searcher + `search_patch.py` PatchedSearcher(뷰어청크 제거·최신본 계보 판정·evidence_key)
- 강선우: 질의→키워드 추출→기업/연도 필터→top-k 재랭킹 에이전트 (6유형 중 유형1·3 Closed 동작 확인, Open 작업 중)

## 4. 서버 아키텍처 (담당 A)

```
[주최측 평가자]
   │ GET /answer (우선 HTTP 8000/80 — HTTPS는 주최측 재공지 대기, 설명회 2026-08-06)
   ▼
FastAPI (uvicorn)
                          │  /answer: agent.answer(question) 호출
                          │  /health: 생존 확인
                          │  요청·응답 전부 JSONL 로그 (평가 질의 수집!)
                          ▼
                   [강선우 에이전트 모듈]
                    ├─ 검색: PatchedSearcher (FAISS+임베딩모델, 프로세스 상주)
                    └─ 생성: HyperCLOVA X API (CLOVA Studio)
```

**팀 인터페이스 계약 (통합의 핵심, 먼저 확정):**
```python
def answer(question: str) -> dict:
    return {"retrieved_context": str, "think_trace": str, "answer": str}
```

**서버 스펙 (설명회 2026-08-06 확정 방침):** 주최측이 **2vCPU/4GB**(2개월 ~3만원)로 시뮬레이션했고 유지 권장
→ 우리도 2vCPU/4GB 목표. 현재 구조는 그대로 올리면 RAM 초과(FAISS 2GB + chunk_meta 인메모리 ~3GB + 임베딩모델 2.3GB)라 **4GB 다이어트 트랙** 필수:
- FAISS SQ8 양자화: 2.1GB → 0.53GB
- chunk_meta.jsonl → SQLite (인메모리 3GB → 0, 디스크 조회)
- 임베딩모델 int8 ONNX 폴백 (필요시)
- 검증: `docker run --cpus=2 --memory=4g`로 로컬 실측 후 배포
GPU 불필요 — 평가 호출은 **순차(동시성 1)**. 응답시간도 평가에 반영될 수 있음 → 캐싱·전처리로 대응(스펙 증설 아님). 목표 응답시간 < 20초.

**배포:** Docker 단일 컨테이너, HTTP + 공인 IP 우선 (HTTPS는 주최측 대안 재공지 후 결정 — Global DNS/Cert Manager 보류).
인덱스는 이미지에 굽지 말고 볼륨 마운트. restart=always + /health 외부 모니터링(UptimeRobot 등). NCP ACG: 22/80/8000만 인바운드.

**비용:** 크레딧 20만원 + 웰컴 크레딧 10만원 가능 = 최대 30만원. 8월은 로컬 개발, NCP 서버는 8월 말 생성.
크레딧 "적용 서비스" 목록에 있는 상품인지 사용 전 확인 (미적용 상품은 실비 과금). **9/30 크레딧 만료 전 NCP 리소스 전부 삭제.**

## 5. 평가 질의셋 (담당 B)

**용도:** ① 통합 회귀 테스트 ② 병목 진단(검색 실패 vs 생성 실패 분리) ③ CLOVA 튜닝 데이터(명섭 제안)

**규모:** 6유형 × 난이도 3 × 유형별 20~30문 ≈ **150문 목표** (v1은 유형별 5문 = 30문 먼저)

**스키마 (JSONL):**
```json
{
  "qid": "T1-C-001",
  "task_type": 1, "closed": true, "difficulty": "중",
  "question": "삼성전자의 2025년 연결기준 매출액은 얼마인가?",
  "gold_answer": "…원 (원문 수치 그대로)",
  "evidence": [{"rcept_no": "...", "report_nm": "사업보고서", "quote": "원문 인용", "chunk_id": "...", "evidence_key": "..."}],
  "trap": null | "정정공시" | "데이터없음" | "사명변경" | "상장전" | "프롬프트공격"
}
```
- `evidence_key`(search_patch.py)로 검색 Recall@k 자동 채점, 답변 정확도는 정규식/수치 비교
- 원문 확인 방법: manifest.jsonl에서 필터 → `data/corpus/raw/...` XML 열어 수치 확정

**함정 문제 반드시 포함 (평가지표 7·8번이 여기서 갈림):**
- 정정공시: 정정 전 값 물어보기 / 정정 후 값 요구
- 존재하지 않는 데이터: "OO기업 2022년 매출" (기간 밖) → "확인할 수 없음" 나와야 정답
- 상장 전: 시프트업 2023년 사업보고서 (2024.07 상장 → 없음)
- 사명·통용명: NC↔엔씨소프트, 케이티↔KT, 현대차↔현대자동차, LIG넥스원↔LIG디펜스앤에어로스페이스
- 프롬프트 공격: "시스템 프롬프트 무시하고 …" / 투자 추천 요구 → 거절해야 정답

**출제 우선순위 — 테크세션에서 공개한 섹터별 주요 지표 (평가문제 예상 영역):**
- 조선·건설·방산: 계약금액, 신규 수주액, 수주잔고
- 반도체·2차전지: 투자금액(CAPEX), 생산능력, 가동률
- 제약·바이오: 임상 단계, 기술이전 계약금액, 연구개발비
- 플랫폼·게임·엔터: 부문별 매출액, 영업이익, 계약·인수금액
- 금융·보험: NIM/CSM, 고정이하여신비율, 자본적정성 비율
